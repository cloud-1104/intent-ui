# 组件交互设计语言

用于后台组件的选择、设计、实现和评审。按需要读取：共同语言、状态、组件选择、浮层与焦点、组合与多输入。具体业务能力仍由 [能力判断](capability-decision.md) 决定。

以下是五个项目的综合提炼和本 Skill 的产品约定；不是官方联合标准。来源分工及冲突处理见 [组件来源](component-sources.md)。

## 共同语言

用同一组问题定义组件：**做什么、作用于谁、现在什么状态、如何操作、何时生效、结果是什么、如何退出或恢复。**

| 原则 | 可执行的设计约定 |
| --- | --- |
| 语义先于外观 | 跳转用链接，执行动作或改变状态用适当控件；原生能力足够时优先使用。给元素添加 ARIA 角色不会自动获得行为 |
| 同义保持一致 | 同一动作的命名、状态、入口与反馈保持一致；“关闭视图”“取消任务”“撤销结果”不共用含混语义 |
| 层级表达任务 | 当前任务的主要动作显著，次要动作较弱，危险性单独可辨；不让一排按钮同等争抢注意，也不把危险按钮默认设为初始焦点 |
| 状态可理解 | 外观、文案、可访问名称和程序状态表达同一事实；聚焦、选中、展开和请求成功分别表达 |
| 响应及时且真实 | 按下有响应、等待可识别、结果可确认；及时反馈不等于提前宣告业务成功 |
| 焦点与上下文连续 | 打开、关闭、删除、校验和刷新后仍能知道操作位置；不无故跳页、抢焦点或重置输入 |
| 渐进展示有边界 | 常用操作和关键限制可发现，补充内容按需展开；不能把必填规则、错误或唯一操作路径藏在悬浮提示里 |
| 动效解释变化 | 动效帮助理解展开、移动、加载和结果，不阻碍再次操作；支持减少动态效果，不靠动画单独传达结果 |

语义依据 [APG 使用前提](https://www.w3.org/WAI/ARIA/apg/practices/read-me-first/)；层级参考 [Carbon 按钮](https://www.carbondesignsystem.com/building-blocks/core/components/button/guidelines)；反馈与上下文参考 Ant Design 的[即时反应](https://ant.design/docs/spec/reaction/)和[足不出户](https://ant.design/docs/spec/stay/)。动效和异步结果边界为本 Skill 的适配。

## 状态是多个维度

不要把所有状态写成互斥枚举；例如一个选中项可以同时聚焦，一个错误字段仍可编辑。只定义该组件适用的状态，不强行让所有组件拥有完整状态集。

| 维度 | 状态含义 | 呈现与行为 |
| --- | --- | --- |
| 输入反馈 | hover、focus-visible、pressed | 悬浮提供补充提示；键盘焦点清晰可见；按下是短暂反馈，不能当作持久选中 |
| 值与展开 | checked、mixed、selected、expanded | 根据语义使用勾选、部分勾选、选中或展开；开关不具有 mixed 状态 |
| 可用性 | enabled、disabled、read-only | 禁用阻止激活；只读保留允许的阅读与复制；隐藏表示当前无展示价值，不能与禁用随意互换 |
| 请求过程 | idle、pending、success、error、unknown | 防止重复，显示真实结果；结果未知先查询。加载不是空数据，发送成功不是业务完成 |
| 校验 | untouched、invalid、valid | 必要时显示就近说明；错误不覆盖焦点提示，正常值无需到处展示成功标志 |

- 稳定的功能标签与当前状态分离：开关名为“邮件通知”，状态为“开／关”；不随状态改成两个不同的功能名称。
- 主次按钮、危险色、焦点环、选中标记使用已有设计系统的语义样式；不把五套品牌颜色、按钮排列或动画时长拼在一起。
- `aria-disabled` 不会自动阻止点击或键盘激活；不能只变灰而继续执行。原生禁用控件与菜单内禁用项的焦点策略不同，按实际模式实现。
- 请求过程中保持对象和动作可辨认，避免按钮宽度或行位置跳动导致误触。可恢复的局部失败不要清空整个组件。

聚焦与选中的区别依据 [APG 键盘接口](https://www.w3.org/WAI/ARIA/apg/practices/keyboard-interface/)；跨输入状态参考 [React Aria Quality](https://react-aria.adobe.com/quality)。

## 组件选择与行为契约

| 用户意图与组件 | 必须说明的交互 | 容易混淆的边界 |
| --- | --- | --- |
| 执行动作：Button | 具体动词、目标、可执行条件、按下与等待反馈；按按钮语义支持 Enter 和 Space | 导航保留链接行为；图标按钮有名称；非提交按钮不意外提交表单 |
| 输入文本：Input／Textarea | 标签、限制、校验、清空含义；保留选择、复制、粘贴及输入法行为 | Enter 不总是提交：多行输入、候选确认、中文输入法组合期间各有语义 |
| 少量互斥选项：Radio | 分组标签、当前值；常规单选组按模式用方向键选择、Space 勾选 | 不用多个开关表达互斥选择；工具栏内单选有不同的方向键约定 |
| 独立选项或多选：Checkbox | 单项选择、组选中和部分选中；Space 切换 | “全选”必须说明本页或全匹配范围；mixed 是组选中程度，不是未知或加载中 |
| 二元设置：Switch | 稳定标签、开关状态、适用的生效时机和失败处理；Space 切换，Enter 依模式可选 | 默认用于立即应用、低影响且可逆的设置；需保存的一组选项优先 Checkbox；需审批或复杂确认用动作流程 |
| 从集合选值：Select／Combobox | 当前值与查询文本分离，键盘浏览和确认、取消、清空规则；异步时有加载、无匹配与错误状态 | 是否允许自由输入要明确；不能因输入文字就把未确认的候选 ID 当成值 |
| 选择命令：Menu／Dropdown | 触发器打开、菜单内导航、执行、退出和焦点去向 | 不因外观是“下拉”就把表单值选择器做成命令菜单；普通网站导航不必套 menu 角色 |
| 切换同层内容：Tabs | 选中项关联内容；Tab 进入或离开标签组，方向键移动，手动模式以 Enter／Space 激活 | 无明显延迟可自动激活；远程加载或切换代价高时用手动激活。分段控件若表达筛选值，应按选择控件建模 |
| 展开补充内容：Disclosure／Accordion | 展开状态、触发按钮、内容关系；Enter／Space 切换，Tab 正常访问可用内容 | 不是 Tabs，不默认给所有标题套方向键模型；单开或多开按任务决定，收起不等于清空数据 |
| 浏览数据：Table／Grid | 普通表格保留表头和内部控件顺序；电子表格式任务才定义网格导航、编辑和退出模式 | 表格有按钮或复选框不自动成为 Grid；使用 grid 角色必须实现对应键盘与焦点行为 |
| 输入日期或数值：专用输入控件 | 格式、单位、范围及必要时区；键盘可操作，错误不丢输入；本地化解析与显示一致 | 普通文本样式不代表可任意解析；精确值任务不能只提供拖动滑块 |

具体键位按 [APG 模式](https://www.w3.org/WAI/ARIA/apg/patterns/)和所选实现核对；核心来源链接见 [组件来源](component-sources.md)。Switch 的即时应用倾向来自 [Carbon Toggle](https://www.carbondesignsystem.com/building-blocks/core/components/toggle/guidelines)，不是 ARIA 对保存时机的强制规定。已有产品若采用随表单保存的 Switch，必须明确说明并保持一致。

异步候选只应用于对应的当前查询，旧请求迟到不能替换新结果或回填已失效值。候选高亮、选值确认和业务提交分别定义；只有明确选择自动确认模式时，才允许焦点或失焦改变待提交值。

## 浮层与焦点

先判断是否必须阻断背景操作，再选择浮层。Drawer、Popover 等名称或外观本身不决定是否模态。

| 类型 | 使用条件 | 焦点、关闭和内容规则 |
| --- | --- | --- |
| Tooltip | 简短、非关键、非交互的补充信息 | 悬浮或聚焦可见，不接收内部焦点；不放按钮或链接，不作为关键说明的唯一载体 |
| Popover／Toggletip | 就近查看或操作少量内容 | 允许交互时有明确打开和退出路径；根据内容与模式安排焦点，不默认困住用户 |
| Modal Dialog | 当前短任务确需暂时阻断背景 | 打开后焦点进入，背景不可交互，Tab 留在内部；名称清楚，关闭后恢复合理位置 |
| Alert Dialog | 重要中断确需立即响应 | 说明后果、提供清晰决策；难以撤销时初始焦点优先安全动作，不能用于一般成功提示 |
| Drawer／非模态面板 | 保留原上下文的详情或辅助任务 | 明确是否模态；非模态允许合理返回背景，有关闭方式且不滥用焦点锁定 |

- 弹窗初始焦点根据任务选择输入、标题或安全动作；长内容不因直接聚焦底部按钮而跳过说明。
- 关闭后通常回到触发器；触发器已删除时，移动到相邻对象或合理的后续位置，不能落到不可见元素或页面根部。
- 点击外部是否关闭按风险和输入保留决定，不把库的默认行为当作业务授权。Esc、关闭按钮、遮罩与返回操作共享未保存检查。
- 有嵌套浮层时，一次 Esc 优先处理当前最内层的活动上下文；下拉取消不能同时关闭父弹窗。输入法正在处理按键时不抢夺其确认或取消。
- 非模态浮层不采用模态的背景禁用和焦点陷阱；真正模态也不能只画遮罩却仍允许背景键盘操作。

Tooltip 内容边界依据 [Carbon Tooltip](https://www.carbondesignsystem.com/building-blocks/core/components/tooltip/guidelines)；模态行为依据 [APG Dialog](https://www.w3.org/WAI/ARIA/apg/patterns/dialog-modal/)，实现模式参考 [Radix Dialog](https://www.radix-ui.com/primitives/docs/components/dialog) 和 [Popover](https://www.radix-ui.com/primitives/docs/components/popover)。嵌套关闭与输入保留属于集成时必须明确的约定。

## 多输入与组件组合

- 鼠标、触控、键盘和辅助技术可以完成同一核心任务，但不必拥有完全相同的手势。触控不依赖 hover；拖拽和长按有适合任务的可发现替代入口。
- 普通按钮在有效激活完成时执行，不在按下瞬间触发不可逆业务；拖出后释放、滚动等取消手势不误激活。沿用原生或成熟组件行为，不重复叠加 click 与 press 导致执行两次。
- 不统一拦截所有方向键、Space 或 Enter。遵守输入框文本编辑、页面滚动和具体复合组件约定；视觉相近的控件也可能键位不同。
- 自定义包装和样式替换后保留语义、标签关联、事件与 ref 所需能力，不出现按钮嵌套按钮。受控状态必须与实际展示及提交结果同步。
- 组合多个交互基础组件时明确谁拥有触发、焦点、关闭和滚动锁定，避免重复管理。Portal、遮挡和溢出裁剪不能破坏浮层可达性。
- 按项目支持范围核验中文输入法、键盘、触控、缩放及必要的 RTL、日期数字本地化；不能因使用某个库就宣称整个页面无障碍合规。

输入行为参考 [React Aria usePress](https://react-aria.adobe.com/usePress)；组合边界参考 [Radix Composition](https://www.radix-ui.com/primitives/docs/guides/composition)。中文输入法、单次执行及状态同步是本 Skill 的集成检查。

输出具体组件规范时，使用 [交付与检查](delivery-and-review.md) 中的组件行为契约；不要只列“默认、悬浮、按下”三张外观图就认为交互定义完成。
