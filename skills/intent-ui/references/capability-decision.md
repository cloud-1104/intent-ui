# 能力判断

本表是面向后台业务的决策框架，不是 Cloudscape 的强制功能清单。判断范围始终是“当前模块、当前角色和当前任务”。

## 判断顺序

1. **任务必要性**：没有该能力，用户能否完成目标？有无可靠的现有替代路径？
2. **业务合法转换**：对象允许这个操作吗？适用于哪些状态、字段和依赖关系？
3. **角色与范围**：谁可见、谁能操作、影响自己的数据还是组织数据？
4. **风险与可恢复性**：失败、重复执行或误操作会造成什么影响，如何发现并恢复？
5. **频率与规模**：是否有证据需要批量、快捷操作、保存筛选或自动刷新？

基础必需限定在适用场景内：例如纯静态说明页不需要网络加载状态，无编辑能力的页面不需要未保存提醒。

## 条件矩阵

“可以省略”意味着下面的触发条件不成立，并非为了省工而删掉已成立的需求。

| 能力 | 何时基础或条件必需 | 可以省略或降级的条件 |
| --- | --- | --- |
| 页面身份、当前位置和返回路径 | 所有可导航业务页面都要能辨认对象和范围，路径要可预测 | 单页工具可不用侧栏和面包屑；不能缺少必要的上下文 |
| 工作台或仪表盘 | 工作从跨模块待办、异常监控或指标判断开始 | 直接进入高频任务更高效时不做；可配置布局通常为可选增强 |
| 数据集合视图 | 用户需要查找、比较或处理多个对象 | 固定单对象配置不必套表格；少量视觉对象可用卡片 |
| 搜索与筛选 | 用户需定位特定对象或工作集合，单靠浏览不足 | 数据少且稳定、可直接定位时省略；先解决常用条件，再加高级组合 |
| 排序 | 优先级、时间、数量等顺序影响判断 | 顺序固定且有业务含义时不用通用排序；不能按无意义字段排序 |
| 分页或分段加载 | 数据量和响应成本使一次展示不可用 | 少量数据不用；不凭空显示无法取得的精确总数 |
| 筛选和浏览位置保留 | 列表与详情间往返属于核心流程 | 一次性短流程可简化；跨登录持久化和保存视图通常可选 |
| 详情 | 列表信息不足以完成判断、需关联对象或记录历史 | 所需信息已完整可读时不强加独立详情页 |
| 新增 | 当前角色负责在本系统创建对象 | 外部同步或系统生成对象不提供虚假的新增入口 |
| 编辑 | 有明确的维护或纠错任务，业务状态允许 | 不可变事件、已封存版本等不提供通用编辑；按业务提供修订或新版本 |
| 复制 | 高频创建相似对象，重填成本明确 | 低频或复制易混淆身份、权限和关联时省略 |
| 删除 | 业务确实允许销毁或删除，且依赖和保留规则允许 | 停用、归档足以完成目标时可不提供删除；规则未知则待确认 |
| 停用与启用 | 对象需要保留但暂停参与后续业务，且状态转换存在 | 不存在可用性生命周期的记录不用开关；不要拿停用代替业务取消 |
| 归档与恢复 | 需从日常工作中移出且继续查询历史 | 无此生命周期时省略；恢复仅在产品支持时提供 |
| 提交、审批、发布、撤回 | 业务有明确审核责任或生效流程 | 简单资料维护不强加审批；已生效对象不默认支持撤回 |
| 批量操作 | 核心工作需重复处理多条，操作语义可批量化 | 低频、必须逐条判断或无法处理混合结果时省略；数量大不自动意味着可批量 |
| 导入 | 工作来源为外部批量数据，逐条录入不能满足任务 | 偶发少量输入可不做；现有同步渠道能可靠完成任务时不重复建设 |
| 导出 | 有离线分析、业务交付或对账任务且授权允许 | “表格通常有导出”不是理由；可用在线视图满足时省略 |
| 附件 | 文件是业务证据、输入或交付物 | 无文件需求时省略；预览、版本、批量上传分别判断 |
| 任务状态与结果回查 | 操作会长时间运行、离页后继续，或结果不能立即确定 | 短同步操作不建任务中心；任务较少可用详情中的状态入口 |
| 操作记录 | 多人协作、权限修改、发布变更或关键操作需追责与恢复依据 | 低影响个人偏好无需逐项展示历史；不凭空规定保留年限 |
| 通知中心 | 离开原页面后仍需知道结果，或任务需后续处理 | 原位反馈已足够时不做；外部通知渠道单独按需求决定 |
| 自动刷新 | 决策依赖持续变化的状态 | 静态配置或用户需稳定选取对象时采用手动刷新 |
| 列设置、密度、保存视图 | 不同角色长期使用同一复杂数据视图 | 简单固定任务省略；个性化不能隐藏关键风险信息 |
| 多租户或环境切换 | 用户被授权在多个组织、项目、环境间工作 | 单一范围不增加切换器 |
| 加载、异常、结果反馈 | 相应数据请求或操作存在即基础必需 | 不用强行做成功弹窗；清晰的原位变化可承担反馈 |
| 权限与可访问性 | 受权限保护的资源、已有交互控件必须正确处理 | 单角色可省复杂角色管理，但不能用前端隐藏代替授权 |

## 操作可用性

先确定产品是否支持操作，再确定当前对象和用户能否执行。把以下问题分别回答：

| 问题 | 应明确的规则 |
| --- | --- |
| 能不能知道这项能力存在 | 长期不适用且无解释价值的入口省略；需要申请权限或理解流程时可展示解释 |
| 当前能不能执行 | 角色权限、数据范围、对象状态、关联依赖和进行中的任务共同决定 |
| 暂时不能执行怎么办 | 说明原因及有用的下一步；可恢复的前置条件优先用禁用和说明 |
| 能看但不能改怎么办 | 用只读内容，保留必要的选择和复制；不把整页变成难读的灰色表单 |
| 条件在提交前变化怎么办 | 重新校验，解释新状态，保留可恢复输入；不要继续执行过期决定 |

业务“已停用”是一种数据状态；按钮“禁用”是一种交互状态，两者不能混为一谈。

## 六类常见场景

这些是带条件的起点，具体业务规则优先。

| 场景 | 常见必需能力 | 常见不适用或待判断能力 |
| --- | --- | --- |
| 管理员维护账号 | 查找、详情、允许字段的修改、角色范围、账号可用状态 | 删除需先判断身份来源及历史关联；外部账号可能只能查看或同步 |
| 审计事件查询 | 时间范围、主体和动作筛选、详情、结果状态 | 人工新增、编辑、停用通常不适用；导出按任务和权限判断 |
| 固定的少量字典项 | 展示、允许的修改、被引用时的限制说明 | 搜索、分页、仪表盘可省；删除与停用由引用规则决定 |
| 工单处理 | 队列、详情、指派、处理状态、必要沟通和历史 | 不提供任意改写状态的通用编辑；批量审批不能从批量指派类推 |
| 配置发布 | 草稿编辑、差异核对、生效范围、发布结果、版本身份 | 审批、定时发布和回滚分别判断；回滚需要实际可恢复版本 |
| 批量数据导入 | 格式说明、预检、范围确认、进度、结果和错误定位 | 能否预览、部分提交和重试取决于导入语义，不能假设总能撤销 |

每项省略决策记录一个重新评估条件，例如“数据不超过用户可直接扫描的范围；随着数据增长或定位反馈出现问题，再引入搜索”，不要虚构统一的数量阈值。
