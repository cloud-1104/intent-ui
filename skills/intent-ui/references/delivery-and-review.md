# 交付与检查

按用户任务裁剪输出。简单模块使用短表和少量规则；全系统规范可用分章节文件。遵循已有文件位置和命名，不自动创建新 Page、改造代码或发布外部内容。

组件专项设计或评审可直接从“组件行为契约”开始，只补充影响选型的业务背景，不强行再输出全系统能力矩阵。

## 模块交互契约

以下结构按需使用，删除不适用字段而不是机械填满占位符。

### 业务背景

- 用户与目标：谁在什么范围内完成什么工作。
- 事实与假设：已有证据、明确规则、仍影响判断的未知项。
- 数据来源与生命周期：谁创建、哪些内容可变、有哪些状态和关联依赖。

### 功能取舍

| 能力 | 分类 | 条件与证据 | 当前取舍 | 重新评估条件 |
| --- | --- | --- | --- | --- |
| 使用业务能力名 | 基础必需／条件必需／可选增强／不适用／待确认 | 具体任务、状态或来源 | 实现、复用、延期或省略及理由 | 何种变化会改变结论 |

分别记录“业务需要但暂缺接口”和“不适用”，避免把实现困难包装成功能可省略。

### 状态与操作

| 当前状态 | 操作 | 有权角色与数据范围 | 前置条件 | 执行中 | 成功结果 | 失败或未知结果 |
| --- | --- | --- | --- | --- | --- | --- |
| 业务状态 | 具体动作 | 谁可执行 | 依赖与限制 | 是否可重复、可取消 | 真实状态和去向 | 保留什么、如何恢复 |

### 页面和操作规则

对每项已选能力说明入口与范围、显示和禁用条件、必要输入、确认强度、执行反馈、错误恢复、返回位置。按需要说明筛选保留、选择范围和无障碍行为，不重复整本通用规范。

### 可验收场景

使用“给定……当……应当……”或等价的具体步骤；预期结果可观察，避免只有“体验良好”“权限正确”“错误友好”。区分已验证、仅设计和依赖后端支持。

## 组件行为契约

在组件选型、状态设计或具体实现需要明确时使用，规则依据见 [组件交互设计语言](component-interaction-language.md)。

| 维度 | 应说明的内容 |
| --- | --- |
| 意图与语义 | 用户任务、所选组件及原因、原生或 ARIA 语义、可访问名称 |
| 状态与生效 | 适用的焦点、选中、展开、禁用、校验和请求状态；输入何时提交、何时生效 |
| 输入与焦点 | 鼠标、触控、键盘的关键操作；进入、内部移动、离开、关闭或删除后的焦点位置 |
| 反馈与退出 | 等待、成功、失败、结果未知；取消、清空、撤销各有什么效果 |
| 组合边界 | 嵌套控件和浮层的事件归属、焦点管理、只读或禁用说明、必要的输入法与本地化约定 |
| 验收 | 至少覆盖本次变化的主流程和容易混淆的边界；实际测试设备或实现依赖明确 |

不要将组件 API 参数清单或状态截图清单当作行为契约；不适用维度直接省略。

## 验收选取

依据本次变更选取，不为每个简单页面运行完整测试矩阵。

| 涉及能力 | 至少考虑的行为 |
| --- | --- |
| 列表加载 | 首次加载、空数据、无匹配、失败、返回位置 |
| 编辑 | 成功、字段错误、服务端失败保留输入、适用的未保存离开 |
| 状态操作 | 合法转换、不允许转换、执行中、依赖或权限变化 |
| 删除 | 取消不改数据、真实成功、依赖阻止、失败、适用的结果未知 |
| 批量 | 跨页范围、混合资格、部分失败、只重试适用项 |
| 长任务 | 受理与完成区分、离页回查、真实取消能力、超时结果查询 |
| 多人或多租户 | 冲突不静默覆盖、切换后选择和数据不串范围 |
| 交互控件 | 语义与标签、核心键盘流程、焦点与选中区别、可访问的错误和禁用说明 |
| 浮层与组件组合 | 初始和返回焦点、模态边界、嵌套关闭、事件不重复、适用的触控与输入法行为 |

规范设计阶段只写验收标准，不声称已经运行。代码实现阶段根据实际风险验证；不能操作生产数据来证明删除或审批流程。

## 现有系统评审

先确定用户任务，再查看该任务的完整流程。截图只能证明可见内容；代码只能证明所检查的实现，无法替代实际服务端和运行时验证。

每个发现包含：所在位置、观察证据、触发条件、用户后果、严重程度、最小修正、验收方式。优先级按本项目实际影响确定：

- **阻断或高影响**：核心任务不能完成、作用范围错误、不可恢复损失、权限范围错误。
- **明显影响效率或可靠性**：失败丢输入、列表上下文丢失、状态不清、部分失败被掩盖。
- **可选优化**：有使用证据支持的快捷方式、个性化或视觉改善。

未实现可选功能不自动成为缺陷。不因缺少新增、删除、导出或仪表盘就判定后台不完整；先证明业务条件成立。

## 场景演练

用这些反例检查规则是否会过度套用；它们不替代具体项目的业务决策。

### 场景 A 只读审计查询

输入：事件由系统生成，用户只能查询；当前没有导出任务。

合理结论：定位事件和查看必要细节；不增加新增、编辑、删除、停用或批量复选框。是否需要独立详情取决于现有信息是否足够。空态不出现“新增事件”。

### 场景 B 五个固定字典项

输入：单一管理员维护显示名称；编号不可变，不支持删除；无复杂查询。

合理结论：清晰展示和修改名称即可；不强加搜索、分页、详情页、审批和仪表盘。编号只读，失败保留修改；少量数据也不能省略真实提交反馈。

### 场景 C 混合状态的批量停用

输入：选中 20 个账号，其中 3 个无操作权限、2 个正在处理，业务允许处理其余账号。

合理结论：执行前说明选中 20、可处理 15、其余不可处理及允许披露的原因；执行时再验证。结果分别报告；重试不再次处理已经完成者。不能只显示“批量成功”。

### 场景 D 长时间导入且超时

输入：已提交导入请求，浏览器未收到结果；服务可能已创建任务。

合理结论：显示结果待查询；通过任务身份或可防重复的协议查找或安全恢复。不能立即再次提交整个文件，不能把关闭对话框当作取消。

### 场景 E 已发布配置

输入：发布版本不可变；当前需求只允许创建新草稿，没有回滚接口。

合理结论：只读发布版本并允许从其创建新草稿；不加入通用直接编辑和虚假回滚按钮。若回滚是后续业务需要，记录实现依赖，不声称已有支持。

### 场景 F 多租户处理中切换

输入：用户在组织 A 选中多条记录后切换组织 B；A 的后台任务继续运行。

合理结论：B 不沿用 A 的选择或可执行操作。A 的任务继续按原范围执行，只有重新进入有权限的 A 范围才显示相应细节；不能把该任务结果更新进 B 的列表。

### 组件边界演练

| 输入场景 | 合理结论与验收重点 |
| --- | --- |
| “提示气泡”中有查看帮助的链接 | 选择可交互面板或常驻帮助，不塞进不接收焦点的 Tooltip；键盘能到达并退出 |
| 标签面板需远程请求，切换明显等待 | 使用手动激活；方向键浏览不连续发起内容切换，Enter 或 Space 确认后才加载 |
| 表格中只有行操作按钮和选择框 | 可保持普通表格语义；不因含按钮就强制 Grid，内部控件正常可达 |
| 弹窗内打开下拉后按一次 Esc | 先处理下拉，焦点回到合理位置，不同时丢弃父表单；输入法按键不被抢夺 |
| 开关只是草稿值，需要整表保存 | 明确“保存后生效”；新设计优先评估 Checkbox，已有约定可沿用，但不能宣称已实时更新 |

这些是行为演练用例，不表示实际组件已经通过运行时测试。
